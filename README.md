# Подготовка записи к офтальмологу

## Приложение с интерфейсом

Готовая версия: `release_gui/Запись к врачу.app` для macOS Apple Silicon.
Открывается двойным кликом, содержит все зависимости и работает без видимых
окон браузера и терминала. Данные вводятся в форме или импортируются из
старого `config.txt`. Для отправки заявки выберите режим «Автоматическая запись».
Статусы, ошибки, сведения о подтверждённом приёме и сохранение PDF доступны
в окне приложения. Инструкция: `release_gui/Как пользоваться.txt`.

Оформление следует светлой или тёмной теме macOS и меняется без перезапуска.
Палитры и стили находятся в `gui_theme.py`, стрелки полей и отметка чекбокса —
в `gui_assets/`. Автономная проверка сохраняет снимки обеих тем, проверяет
переключение через системный сигнал Qt и клики по стрелкам времени и длительности.
Исходник иконки приложения — `gui_assets/app-icon.png`. Сборщик преобразует его
в набор размеров macOS и включает `AppIcon.icns` в приложение для Finder и Dock.

Фон использует NSVisualEffectView из AppKit через небольшой встроенный модуль
`native/macos_backdrop.m` и `gui_backdrop.py`. Сборщик компилирует его системным
Clang (нужны Command Line Tools) и включает библиотеку в .app. Пакеты PyObjC
пользователю не нужны. При недоступности нативного эффекта остаётся обычный фон.
Учитывается системное уменьшение прозрачности. Автономная проверка дополнительно
проверяет нативный фон после изменения размера, прозрачность поверхности Qt и
плашки всех неуспешных результатов при минимальном размере окна в обеих темах.

Исходники: `talon_gui.py` (Qt), `gui_backend.py` (скрытый браузер и PDF).
Используются общие модули `talon.py` и `booking.py`. Отмена до отправки
прекращает запись; после отправки приложение дожидается результата.
Ошибки экспорта PDF не меняют подтверждённую запись на неуспешную.

Сборка и автономные проверки:

```sh
.venv/bin/python -m pip install -r requirements-gui.txt
.venv/bin/python build_gui.py
PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" .venv/bin/python -m unittest test_talon test_booking test_gui
"release_gui/Запись к врачу.app/Contents/MacOS/Запись к врачу" --self-test-report /tmp/talon-gui/report.json
```

Проверены 50 тестов: конфигурация, восстановление после сбоев, браузерная
запись, отмена, экспорт и форма. Полный сценарий дополнительно пройден
в собранном приложении с перехватом всех запросов и синтетическими данными:
ошибка 503, восстановление, одна отправка, сведения о приёме и PDF по кнопке.
Реальные записи при этих проверках не создаются.

Сборщик должен иметь возможность запускать Qt: в ограниченной песочнице
определение возможностей процессора может завершиться ошибкой. Личные
конфиги и результаты не включаются в сборку. Прежний комплект `release/`
сохраняется; приложение можно переносить отдельно от исходников.

## Автономная версия

Готовый комплект для macOS Apple Silicon находится в `release/`:
`Запись.command`, `config.txt`, `README.txt`. Зависимости и отдельный Chromium
упакованы внутрь исполняемого файла. Для использования достаточно скопировать
эти три файла, заполнить конфиг и открыть `Запись.command` двойным кликом.
По умолчанию выбран режим проверки без создания записи. Инструкция пользователя
находится в `release/README.txt`; исходный шаблон — в `portable/`.

Врач определяется по полному ФИО из конфига; ID извлекается автоматически.
Временные ошибки чтения расписания и проверки пациента повторяются с
увеличенной паузой до конца окна, без ограничения в восемь ошибок, а
неопределённый результат уже отправленной заявки блокирует повторную отправку.
Каждый запуск ограничен своим окном времени и не создаёт ежедневного задания.

Исходники новой версии: `talon.py` (конфиг, расписание, восстановление и запуск)
и `booking.py` (проверенный процесс заполнения формы). В исполняемый файл входят
оба модуля; держать их рядом с ним не нужно.

Сборка на macOS arm64:

```sh
.venv/bin/python -m pip install -r requirements-build.txt
.venv/bin/python build_portable.py
```

Перед сборкой должен быть установлен Chromium для Playwright 1.56.0 в
`.browsers/chromium-1194`. Сборка использует только явно указанные исходники
и этот браузер; `client.md`, `private/` и реальные пациенты в неё не входят.
Существующий `release/config.txt` при повторной сборке сохраняется.

Проверки:

```sh
.venv/bin/python -m unittest -v test_talon test_booking
./release/Запись.command --self-test --no-pause
```

Проверены 25 случаев конфигурации/восстановления и 16 браузерных сценариев с
перехватом всех запросов. Автономная копия проверена в отдельной папке с
минимальным системным PATH и через открытие Finder. Реальных заявок эти
проверки не отправляют.

Ниже сохранена документация предыдущих вспомогательных сценариев разработки.

Первый этап — ручная проверка формы в отдельном локальном браузере.
`prepare_browser.py` открывает ссылку на поликлинику и специальность, но не
выбирает врача, не проверяет талоны и не отправляет запись. `monitor.py` умеет
проверять наличие талонов и начинать проверки в указанное время. `booking.py`
добавляет выбор талона, ввод пациента и подтверждение. 11 ноября 2026 года
пройдена живая репетиция с созданием настоящей записи для тестового пациента.

## Установка

В терминале из папки проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
PLAYWRIGHT_BROWSERS_PATH="$PWD/.browsers" .venv/bin/python -m playwright install chromium
```

## Пробный запуск

```sh
.venv/bin/python prepare_browser.py
```

В открывшемся браузере пройдите вход, выберите пациента и врача вручную.
Остановитесь до подтверждения записи. Для настройки следующего этапа нужно
выяснить:

- какой способ входа используется и когда возникает капча или SMS;
- можно ли оставаться на странице нужного врача и обновлять список талонов;
- какие шаги остаются после выбора времени.

Для основной записи пользователь разрешил любой доступный талон к врачу 839
и автоматическое подтверждение. Это разрешение не распространяется автоматически
на создание записи во время репетиции у другого врача.

Личные данные вводятся только на сайте. Не добавляйте в проект пароли, полис,
паспорт, cookies или экспорт сеанса. Сценарий не сохраняет состояние входа;
после закрытия браузера при следующем запуске потребуется новый вход.

## План следующего этапа

Живая репетиция выполнена. Основной запуск настраивается отдельно.
Частота запросов и механизм обновления должны учитывать поведение сайта.
При капче, истечении входа или изменении формы сценарий должен остановиться и
попросить участия пользователя. После неопределённого результата отправки
сначала проверяется список записей, повторная отправка вслепую не допускается.

Для работы вечером компьютер должен быть включён и подключён к интернету;
браузер нужно подготовить заранее. Расписание появления талонов в 21:00
сообщено пользователем и пока не проверено.

## Мониторинг без входа

Проверенный публичный запрос сайта возвращает список офтальмологов поликлиники
172. Сценарий проверяет ID врача `839` и фрагмент имени «Мирагасы Кызы», затем
читает `freeTicketCount`. Это показатель доступности из списка врачей, а не
резервирование конкретного талона; данные сайта могут обновляться с задержкой.

Одна проверка (не требует Playwright):

```sh
python3 monitor.py
```

Проверки каждые 5 секунд в течение максимум 10 минут:

```sh
python3 monitor.py --watch
```

Старт около 21:00 по Москве — замените дату на нужную будущую дату:

```sh
caffeinate -i python3 monitor.py --watch --at 2026-11-11T20:59:50
```

Запустите команду заранее и оставьте терминал открытым. `caffeinate` препятствует
автоматическому сну при простое; крышку ноутбука оставьте открытой. Скрипт не
устанавливает системное расписание и не запускается самостоятельно после перезагрузки.
При обнаружении талонов он напечатает сообщение, подаст терминальный звуковой
сигнал (если включён в терминале) и остановится. Браузер нужно открыть отдельно
заранее. Любая HTTP-ошибка останавливает мониторинг; временные сетевые ошибки
повторяются с увеличенной паузой не более трёх раз. Остановка вручную — Ctrl+C.

## Запись через браузер

Сценарий `booking.py` использует обычную форму сайта: список врачей → доступный
талон → фамилия, имя и дата рождения → проверка пациента → подтверждение записи.
Для основного пациента отчество, телефон и почта должны оставаться пустыми.
Данные можно импортировать из локального `client.md`, не выводя их в чат:

```sh
.venv/bin/python import_clients.py
```

Поддерживаются разделы «Для реальной записи:» и «Для репетиции:» с полями
«Фамилия:», «Имя:», «Дата рождения:» и «id врача:». Отчество и контакты не
импортируются. При подготовке используются ID 839 (основной врач) и 1562 либо
1918 (репетиция). Конфигурации сохраняются в `private/`.

Локальный ввод данных основного пациента без отображения вводимого текста:

```sh
.venv/bin/python enter_patient.py
```

Данные сохраняются в `private/main.json` с правами 0600. Каталог `private/`
исключён из Git. Поля конфигурации приведены в `booking.example.json`.
Для другого врача нужно указать его district/lpu/speciality/doctor_id и фрагмент
имени, а также другого пациента. В журналы ФИО и дата рождения не записываются.
Сохранённые данные нужны для фонового запуска и остаются локально до удаления.

Репетиция с видимым браузером, без финального подтверждения:

```sh
.venv/bin/python booking.py --config private/rehearsal.json --headed
```

Без `--commit` отправка запроса создания записи заблокирована. Проверка пациента
при этом отправляет введённые данные на сайт. Чтобы репетиция дошла до формы,
у выбранного врача должны быть доступные талоны.

Фоновый запуск основной записи (дату нужно сверить перед запуском):

```sh
.venv/bin/python arm_booking.py --config private/main.json --at 2026-11-11T20:59:45 --minutes 15 --commit
```

Команда запускает отдельный процесс под `caffeinate`, печатает PID и путь журнала.
Браузер открывается за три минуты до указанного времени, затем каждые пять секунд
проверяется список врачей. При появлении мест выбирается первый доступный талон
на отображаемую дату; ограничений по времени приёма нет. Завершение окна — через
15 минут после указанного старта. Компьютер должен оставаться включённым с
открытой крышкой; после перезагрузки процесс не восстановится. Запуск не создаёт
системного задания и не повторяется на следующий день.

Перед отправкой программно проверяются поликлиника, талон и пациент, без паузы
для ручной проверки сводки. Каждый талон отправляется один раз, начало сохраняется
на диск. При явном ответе сервера «талон уже занят» сценарий исключает этот талон
и пробует другой. После подтверждения сервером сохраняется
статус `confirmed`, ID врача и время приёма. При неопределённом результате
сохраняется признак отправленной попытки: перезапуск не отправит её повторно.
Проверять фактический результат в таком случае нужно вручную. Другие ошибки
формы или запроса останавливают автоматическую запись; неизвестная ошибка не
считается доказательством того, что талон занят.

После успеха сохраняется PNG финального экрана рядом с результатом в `private/`.
Фоновый запуск оставляет видимый браузер открытым для печати или сохранения PDF;
после сохранения талона окно нужно закрыть. При прямом запуске `booking.py` для
этого используются параметры `--headed --keep-open`.

## Проверки

```sh
.venv/bin/python -m unittest -v test_booking
```

Десять проверок запускают Chromium с перехватом всех запросов: тестовые пациенты
и талоны не отправляются на настоящий сайт. Проверяются репетиция, успешная
однократная запись, отсутствие пациента, отказ сервера, защита от повторной
попытки, переход к другому занятому талону, сохранение PNG, запрет скрытых маской
данных и несовпадение врача/пациента/талона. Эти тесты не заменяют живую репетицию.
